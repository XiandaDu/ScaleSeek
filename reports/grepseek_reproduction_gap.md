# GrepSeek：论文数值和我们的复现为什么差近 5 分

2026-11-21。结论：**差距来自平均方式，不是复现出了问题。** 逐数据集看，我们的复现和论文一致；BCP 上的差距来自语料格式。

论文数值取自 arXiv 2605.29307v2 的 Table 1（F1）、Table 6（EM）和 Table 2（评测集大小）。脚本：`reports/scripts/grepseek_repro_gap.py`。

---

## 1. 看起来差在哪

| | 我们的表 | 论文 / README | 差 |
|---|---:|---:|---:|
| 7 个 QA 数据集 EM | 45.2 | 49.48 | −4.3 |
| 7 个 QA 数据集 F1 | 54.0 | 56.91 | −2.9 |
| BrowseComp-Plus | 21.6 | 34.22（Table 1）/ 26.02（Table 6） | −12.6 / −4.4 |

## 2. QA 数据集：两个数字用的不是同一种平均

- 我们的 45.2 是 **500 题子集的 micro 平均**（每个数据集 500 题，Bamboogle 125 题，共 3,125 题）。
- README 的 49.48 是 **7 个完整数据集的 micro 平均**（共 51,713 题），等价于按完整题数加权。用论文 Table 6 的逐数据集数值按 Table 2 的题数加权，正好算回 49.48（F1 算回 56.91）。
- 论文主表（Table 1）用的是第三种：8 个数据集的宏平均（F1 52.26，EM 43.47）。

**把同一组数字换成同一种平均，差距就没了**

| 平均方式 | 用论文的逐数据集数值 | 用我们的逐数据集数值 |
|---|---:|---:|
| 我们的方式（子集 micro）EM | **45.33** | **45.22** |
| 论文 README 的方式（按完整题数加权）EM | **49.48** | **49.70** |
| 7 个数据集宏平均 EM | 45.96 | 45.86 |
| 我们的方式 F1 | 53.96 | 53.96 |
| 论文 README 的方式 F1 | 56.91 | 57.36 |
| 7 个数据集宏平均 F1 | 54.83 | 54.69 |

**为什么两种平均差 4 分**：各数据集难度差别很大，而两种方式给的权重不同。

| 数据集 | GrepSeek EM | 子集 micro 的权重 | 按完整题数的权重 |
|---|---:|---:|---:|
| TriviaQA | 约 70 | 16.0% | 21.9% |
| PopQA | 约 44 | 16.0% | 27.6% |
| 2Wiki | 约 46 | 16.0% | 24.3% |
| HotpotQA | 约 48 | 16.0% | 14.3% |
| NQ | 约 40 | 16.0% | 7.0% |
| MuSiQue | 约 21 | 16.0% | 4.7% |
| Bamboogle | 约 51 | 4.0% | 0.2% |

最难的 MuSiQue 在我们的口径里占 16%，在论文口径里只占 4.7%；最容易的 TriviaQA 从 16% 变成 21.9%。

## 3. 逐数据集：都在抽样误差内

| | NQ | TQA | PopQA | HotpotQA | 2Wiki | MuSiQue | Bamboogle | 平均差 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| 论文 EM | 40.47 | 69.25 | 43.63 | 49.49 | 46.27 | 21.43 | 51.20 | |
| 我们 EM | 39.0 | 70.4 | 44.4 | 47.6 | 46.8 | 21.6 | 51.2 | |
| 我们 − 论文 | −1.5 | +1.2 | +0.8 | −1.9 | +0.5 | +0.2 | 0.0 | **−0.11** |
| 我们的 95% 区间半宽 | 4.3 | 4.0 | 4.4 | 4.4 | 4.4 | 3.6 | 8.8 | |
| 论文 F1 | 52.23 | 76.73 | 48.61 | 62.31 | 51.78 | 30.06 | 62.12 | |
| 我们 F1 | 51.9 | 78.7 | 50.4 | 59.3 | 51.7 | 30.0 | 60.8 | |
| 我们 − 论文 | −0.3 | +1.9 | +1.8 | −3.0 | 0.0 | 0.0 | −1.3 | **−0.14** |

- 差别有正有负，平均接近 0，没有系统性偏低。
- 差得最多的是 HotpotQA（EM −1.9）。这是我们抽到的 500 题偏难：在另外 500 道 HotpotQA dev 题（验证集）上，同一个 GrepSeek 的 EM 是 52.2 和 51.0，高于论文的 49.49。

## 4. 我们和论文设置的不同之处，逐项核对

| 不同之处 | 影响 | 依据 |
|---|---|---|
| 每个数据集只评 500 题子集 | 每个数据集 ±4 的抽样误差，无系统偏差 | §3 |
| 所有方法加 presence_penalty 2.0（论文不加） | 没有可见影响 | 验证集 1,000 题各跑两遍：不加惩罚 46.8 / 46.5，加惩罚 46.5 / 46.1；合并比较 46.6 对 46.3，互有胜负 119 对 112，p = 0.69 |
| vLLM 版本、单卡而不是双卡 | 没有发现影响 | 逐数据集数值与论文一致 |
| BCP 语料一行是一整篇网页（论文切成 700 词一段） | **BCP 上低 8 分** | §5 |
| BCP 用 Qwen3-32B 判分、500 题（论文 GPT-4.1、830 题） | 未单独量化 | |

## 5. BrowseComp-Plus：差距来自语料格式

论文附录 A 写明把 100,195 篇文档切成 864,837 段（700 词一段，步长 630 词）。我们原来的语料一行是一整篇网页，一次 grep 基本只能看到一篇文档的开头。

| | judge 准确率 |
|---|---:|
| 我们原来的设置（整篇网页一行） | 21.6 |
| 按论文方式切段（862,948 段） | **29.6**（+8.0，赢 75 输 35，p = 0.0002） |
| 论文 | 34.22（Table 1）/ 26.02（Table 6） |

切段后落在论文两张表的数字之间。

## 6. 结论

- 我们的 GrepSeek 复现是忠实的：7 个 QA 数据集逐个与论文一致，BCP 在对齐语料格式后也一致。
- 表里的 45.2 和 README 的 49.48 不能直接比。要和论文比，应该用同一种平均：按论文 README 的口径我们是 49.70（论文 49.48），按论文主表的口径（8 个数据集宏平均，BCP 用切段版）EM 是 43.83（论文 43.47）、F1 是 51.55（论文 52.26）。
- 建议：论文表格里注明平均方式；如果想让表里的数字和 GrepSeek 论文可直接对照，可以加一列“按完整题数加权”的平均，或者改用宏平均。BCP 一行建议用切段版的 29.6，否则基线偏低。
