# 主会方向的零训练验证（第一轮）：三个都没过门槛

2026-11-20。论点是“接口修好之后，瓶颈从检索转到用证据和决定何时作答”。在验证集上做了三个零训练验证（500 道 NQ dev + 500 道 HotpotQA dev，GrepSeek 官方 checkpoint，GrepSeek+ 环境）。门槛：等计算量下比 GrepSeek+ 高 3 分以上。**三个都没达到，这个论点按事先约定放弃。**

GrepSeek+ 单条轨迹三次运行：50.1 / 49.4 / 49.2。

| 实验 | 做法 | 严格 EM | 相对 GrepSeek+ | 计算量 |
|---|---|---:|---|---|
| 1a 单条重读 | 一条轨迹的工具调用和输出重放进干净上下文，去掉推理，只给一轮作答 | 48.8（不作答时退回原答案）；46.0（不作答算错） | −1.3 / −4.1 | 1 条轨迹 + 1 次作答 |
| 1b 合并重读 | 两条轨迹的证据合并去重后重读 | 50.6 / 49.4 | +0.5 / −0.7（不显著） | 2 条轨迹 + 1 次作答 |
| 2 出处核验 | 答案在所有工具输出里都没出现时，要求再查一次核对（每题一次，轮数预算不变） | 49.0、49.6（两遍） | −1.1 到 +0.2（不显著） | 1 条轨迹，≤ 6 轮 |
| 3 一致就提交，否则合并重读 | 两条轨迹答案相同（70.4%）直接提交，不同时用 1b 的答案 | 50.8 | +0.7（不显著） | 2 条轨迹 + 30% 的题多一次作答 |
| 对照：3 条轨迹多数投票 | | 51.0 | +0.9（p = 0.20） | 3 条轨迹 |
| 3 的最好变体 | 不一致时用第三条轨迹加合并重读一起投票 | 51.7 | +1.6（p = 0.017） | 约 2.3 条轨迹 + 30% 的题多一次作答 |
| 上界：3 条轨迹任一答对 | | 57.1 | | |

**为什么不成立**
- **干净上下文重读反而变差。** 单条重读把 61 道原来答对的题改错，只把 20 道改对。模型原来的推理链是有用的，去掉它损失比“锚定在旧猜测上”造成的损失大。
- **合并证据有一点帮助但不够。** 合并重读比单条重读高 1.8 分，改对 42 道、改错 49 道，净值为零。
- **核验几乎不改变结果。** 每遍约 92 道题被质疑，其中约 2/3 又查了一次，约 77% 保留原答案；被质疑的题里答对的从 13 道变成 18 道（另一遍 12 → 15），折合不到 0.5 分。
- **选不出对的那条。** 3 条轨迹任一答对是 57.1，但多数投票只有 51.0。两条轨迹答案相同时仍有 37% 是错的，这些是系统性错误，换一条轨迹不会变。

**剩下的错在哪**（GrepSeek+ 单条轨迹，占全部验证题）

| 类别 | 占比 |
|---|---:|
| 答对 | 50.1% |
| 答错，没见过 gold | 19.7% |
| 答错，见过 gold（非形式问题） | 15.5% |
| 答错，答案包含 gold（并列候选、过度具体） | 6.0% |
| 答错，gold 包含答案（不够具体） | 5.9% |
| 没给出答案 | 2.8% |

- 答案形式的近似命中合计 11.9%；按“答案包含 gold 就算对”是 56.1；答错但 F1 ≥ 0.5 的题占 16.0%。
- 两条轨迹答案相同且都错的题占 25.9%：没见过 gold 9.0%，见过 gold 8.8%，答案形式 8.1%。

**结论**：零训练的测试时技巧（重读、核验、投票）在这个 checkpoint 上拿不到 3 分。剩下最大的、机制明确的一块是答案形式（约 12%），它来自 GrepSeek 训练时用的 F1 奖励，只能靠训练修。
